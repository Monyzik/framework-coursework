# Курсовой проект

Исследуем влияние ручного и искусственного обогащения данных.

## Данные

- **Fashion 4.0.0** — 3922 фотографии и 5500 масок для четырёх классов:
  рубашки и блузки, футболки, майки и топы, брюки, платья.
  [Скачать набор](https://huggingface.co/datasets/Monyzik/fashion-4000).
- **RuSpellGold** — 1711 пар «текст —
  исправление». [Источник](https://huggingface.co/datasets/RussianNLP/RuSpellGold/blob/8b6694e45ac9222bc705ee4af9d6367ac083ff5c/data/complete_test/test.json).

Данные сохраняются локально:

- `data/raw/imaterialist/` — описания классов и папка `train/` с фото.
- `data/raw/ruspellgold/test.jsonl` — текстовый датасет, одна JSON-запись на строку.
- `data/processed/` — список выбранных фото и их аннотации.

RuSpellGold опубликован только как тестовый набор. Разбиения для обучения ещё нужно определить.

Ноутбук считает статистику итоговой выборки по опубликованным маскам 4.0.0.
Полный `train.csv` используется для анализа исходного набора.
Загрузчик обновляет выборку из `fashion-4000-metadata.zip`. Полный архив
скачивается при отсутствии нужных JPG.

| Код | Класс | Фото | Маски |
| --- | --- | ---: | ---: |
| 0 | Рубашки и блузки | 438 | 441 |
| 1 | Футболки, майки и топы | 1522 | 1553 |
| 6 | Брюки | 1748 | 1753 |
| 10 | Платья | 1747 | 1753 |

Очистка убрала 314 масок класса 1 и 78 фото без оставшихся целевых вещей.
14 спорных объектов перечислены в [журнале повторной проверки](https://huggingface.co/datasets/Monyzik/fashion-4000/blob/4b3e23d4c0a7efe634b410bacbb44624871d314f/cleaning/review_pending.csv).

Одна маска соответствует одному предмету одежды. На одном фото может быть
несколько масок с одинаковым `ClassId`. Такое фото учитываем один раз в частоте
класса, а все его предметы — в числе объектов.

## Запуск

Нужен Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e .
```

Откройте `notebooks/fashion.ipynb` или `notebooks/text.ipynb` и выполните ячейки по порядку. Ноутбуки установят
недостающие библиотеки и скачают данные. Готовые локальные файлы используются повторно.

Скрипты: `scripts/install_dependencies.py` и `scripts/download_data.py`.

## Разметка текста

Каждый разметчик запускает Docker на своём компьютере и выполняет `docker compose up -d`
из папки проекта. Откройте `http://localhost:8080` и создайте проект для текста.
Проекты и разметка хранятся в томе Docker. Остановка через `docker compose down` сохраняет данные.

Вставьте этот XML в настройки проекта **Labeling Interface → Code**.

```xml
<View>
    <Style>.htx-text { white-space: pre-wrap; }</Style>
    <Text name="source" value="$text"/>
    <TextArea name="correction" toName="source" rows="5" editable="true"
              required="true" maxSubmissions="1" placeholder="Вставьте полный текст"/>
</View>
```

## Разметка одежды

Каждый разметчик запускает Docker на своём компьютере и выполняет `docker compose up -d`
из папки проекта. Откройте `http://localhost:8080` и создайте проект для одежды.

Вставьте XML ниже в **Settings → Labeling Interface → Code** и сохраните настройки.
Если в старом проекте уже есть разметка с прежними названиями классов,
создайте новый проект, чтобы сохранить выполненную работу.

Распакуйте `fashion_label_studio_clean.zip`. В локальной копии проекта архив лежит
в `data/manual/`. В проекте нажмите **Import → Upload Files**, выберите все
JPG из папки `batch_01` и завершите импорт. Повторите для `batch_02`.
В версии из `compose.yaml` можно загрузить до 100 файлов за один импорт.
В `batch_01` 99 фото, в `batch_02` 96. После обеих загрузок в проекте должно быть 195 задач.

[Архив на Hugging Face](https://huggingface.co/datasets/Monyzik/fashion-4000/blob/4b3e23d4c0a7efe634b410bacbb44624871d314f/manual/fashion_label_studio_clean.zip).

```xml
<View>
    <Image name="image" value="$image" zoom="true" zoomControl="true"/>
    <PolygonLabels name="garment" toName="image">
        <Label value="Рубашка или блузка" background="#9333EA"/>
        <Label value="Футболка, майка или топ" background="#2563EB"/>
        <Label value="Брюки" background="#15803D"/>
        <Label value="Платье" background="#BE185D"/>
    </PolygonLabels>
</View>
```

Обведите видимую часть каждого предмета нужного класса отдельным полигоном.
Футболка и раскрытая рубашка поверх неё — два предмета с разными метками
классов 1 и 0. Две рубашки — два предмета с одинаковой меткой класса 0.
Несколько вещей одного класса у разных людей также размечаются отдельно.
Если ткань одной вещи разделена рукой или волосами, обведите каждую видимую
часть отдельным полигоном. Выберите часть, нажмите **Create Relation** и
укажите другую часть той же вещи. В этом проекте связь означает «части одной
вещи». Перед переводом в RLE объедините связанные полигоны в одну маску;
разные вещи с одинаковой меткой не объединяйте. Для сохранения связей
выгружайте полный **JSON**.
Джинсы и спортивные брюки относятся к классу «Брюки». Если на фото нет
предметов этих четырёх классов, нажмите **Skip**. Размечайте видимые части рубашек
и под другой одеждой.

Свитера, свитшоты, худи, вязаные пуловеры, жилеты и кардиганы оставляйте фоном.
Поло и тонкие лонгсливы или водолазки из футболочного трикотажа входят в класс 1.
Пять фото без целевых вещей исключены из ручного дополнения. Решения по снимкам
записаны в `data/manual/cleaning_review.csv`. Полигональную разметку ведём в Label Studio.

В локальном Label Studio настроен проект
[«Одежда — 195 фото (версия 4.0.0)»](http://127.0.0.1:8080/projects/5/data):
195 задач, из них три размеченных примера для codebook (490, 491 и 492).
Импорт примеров и фото с разметкой находятся в `data/manual/label_studio_clean_examples/`.
Предыдущие проекты доступны в Label Studio для истории.

Подробные правила и примеры находятся в
[codebook в Google Docs](https://docs.google.com/document/d/1lx5aaPe3wv-ph6kmOpC8_nrCsd7wjaRdiBpKLUwXsyA/edit).
